# Agent tips: Owner content

Technical lessons for the coding agent in this area, each naming the project that learned it.
Read them before working here. A new lesson in this area goes to the project's *Upstream
candidates* in the moment, and the lesson harvest adds it here.

- **In an interview, people volunteer private details and then ask to keep them out.** Redact
  them in the private notes too (a placeholder plus a rule saying what it stands for and where it
  mustn't go), and search the public repo for earlier mentions (alexanderwebber.com).
- **Figures the owner volunteers from a data export still need their confirmation** before a
  story uses them: the export missed activities recorded in other apps.
- **If the owner wants to review a multi-part draft once, at the end,** keep a clean
  read-through file apart from the working notes, with the choices still open marked inline.
- **For a personal story in a public repo, tell the specify subagent what mustn't appear, then
  search its output yourself.** Keep the owner's raw answers in a private file the next session
  can find. Write the brief from the owner's exact words: "no one else in the family appears"
  became "names no one else" in a brief and reached the spec, where it would have banned
  crediting a published source. Only the agent's own read of the spec caught it.
- **An owner's screenshot can show something other than their complaint.** A screenshot sent
  about a cut-off button showed the button whole and a card's foot cut. Say what the screenshot
  shows, and ask which one they mean before changing anything.
